C++・Pythonの整数除算と浮動小数点誤差：整数化の使い方

著者: rikuto yamada · 更新日: 2026年10月15日

対象: 灰〜緑コーダー (Rating 0 ~ 1199) 分野: 競プロテクニック / 数値計算 読了時間: 約 7 分

AtCoder などの競技プログラミングにおいて、アルゴリズムの考え方は合っているのに「なぜか想定と違う値になる」「テストケースの特定の値で WA（誤答）が出る」という経験はありませんか？

その最大の原因の 1 つが「小数・浮動小数点数の扱い」です。
コンピュータの数値表現の仕組み上、小数を含む計算には「整数割り算によるゼロ切り捨て」や「浮動小数点数（double型）の丸め誤差」という危険な罠が潜んでいます。

この記事では、小数が引き起こすバグの仕組みをわかりやすく整理した上で、丸め誤差を避けるための「式全体を定数倍して整数化する（整数だけで解く）」手法を徹底解説します！

1. 小数が引き起こすバグの 2 大原因

① 整数同士の割り算による「切り捨て (Truncation)」

C++ や Java では、整数型同士の除算 / は小数部分をゼロ方向に切り捨てます。Python 3 の / は異なり、整数同士でも浮動小数点数を返します。

// C++ での計算例 int a = 6 / 1000; // 0.006 ではなく「0」になる！ int b = 9 / 10; // 0.9 ではなく「0」になる！
# Python 3 での計算例 6 / 1000 # 0.006（浮動小数点除算） 6 // 1000 # 0（床除算） -9 // 10 # -1（負の無限大方向。C++ の -9 / 10 は 0）

言語別の仕様はPython公式の算術演算仕様とC++標準草案の除算仕様で確認できます。

🚨 実際の競プロでの被弾例: ABC113 B - Palace

標高 $H_i$ での気温が $T - H_i \times 0.006$ と与えられ、目標気温 $A$ に最も近い地点を探す問題です。
$0.006 = \frac{6}{1000}$ なので、コードに以下のように書いたとします。

// 誤ったコード例 (C++) double temp = T - H[i] * (6 / 1000); // (6 / 1000) が 0 に評価されてしまう！

`(6 / 1000)` が `0` に計算されるため、`H[i]` が何であれ `temp = T - 0 = T` となります。
すべての地点の温度を同じ（T）と扱ってしまい、本来選ぶべき地点と異なる答えを出す原因になります。

② 浮動小数点数 (`double`) の「丸め誤差・精度限界」

コンピュータ内部では数値を 2 進数で管理するため、`0.1` や `0.006` といった小数は 2 進数で無限小数になり、正確な値を保持できません。

// 浮動小数点数の精度落ちの例 double x = 0.1 + 0.2; // x は 0.3 ではなく「0.30000000000000004...」になる！ if (x == 0.3) { // ここは実行されない（一致しない）！ }

例えば、本来5になる計算結果が丸め誤差で 4.99999999999 になると、floor(x) や整数へのキャストは4になります。ceil は切り上げなので、同じ値には5を返します。

2. 比較を正確にする方法: 「式全体を定数倍して整数化する」

分数や有限小数を含む比較では、式全体を正の定数倍して整数だけで計算すると、浮動小数点の丸め誤差を避けられます。ただし、途中の積や差も含めて整数型の範囲に収まることを確認してください。

✨ 定数倍による整数化の原理

値の大小関係の比較や最小値のインデックス探索において、正の定数 $K$ を式全体に掛け合わせても、大小関係や最小値を与える位置は一切変わりません。

【実践例 1】 ABC113 B - Palace を 1000 倍して整数化する

目標気温 $A$ と地点 $i$ の気温 $T - 0.006 \times H_i$ の差の絶対値を最小化したい問題です。

元の最小化対象の式:

$|A - (T - 0.006 \times H_i)|$

ここで $0.006 = \frac{6}{1000}$ なので、式全体を 1000 倍します:

$1000 \times \left|A - \left(T - \frac{6 H_i}{1000}\right)\right| = |1000 \times A - (1000 \times T - 6 \times H_i)|$

さらに整理すると、以下の美しい整数式になります:

$|1000 \times (T - A) - 6 \times H_i|$

この値が最小となる地点 $i$ を探せば、この比較を浮動小数点の丸め誤差なしに計算できます。問題の制約から、途中の積と差が long long の範囲に収まることも確認します。

// ABC113 B の制約で1000倍して整数化する例（C++） #include <iostream> #include <vector> #include <cstdlib> #include <limits> using namespace std; int main() { int N; long long T, A; cin >> N >> T >> A; long long min_diff = numeric_limits<long long>::max(); int best_index = 1; for (int i = 1; i <= N; i++) { long long H; cin >> H; // 1000倍して整数化した絶対値差を計算 long long diff = abs(1000 * (T - A) - 6 * H); if (diff < min_diff) { min_diff = diff; best_index = i; } } cout << best_index << endl; return 0; }

【実践例 2】 分数の比較 $A / B < C / D$ を通分して整数化

2 つの割合や平均値を比較したい時、`(double)A / B < (double)C / D` と計算するのは精度落ちの危険があります。

$B$ と $D$ が正である場合、両辺に正の数 $B \times D$ を掛けて通分（クロス掛け算）できます:

$A \times D < C \times B$

これにより、積が整数型の範囲に収まれば正確に比較できます。分母が0の式は扱えません。負の分母は先に符号を分子へ移すか、掛ける数が負なら不等号が逆になることを考慮します。

【実践例 3】 平均値 $\sum A_i / N \ge X$ の判定

要素数 $N$ が正で、平均値が $X$ 以上かを判定する場合も、両辺に $N$ を掛けます:

$\sum A_i \ge X \times N$

合計値 $\sum A_i$ と $X \times N$ を比べることで、割り算なしで一瞬で判定できます。

3. どうしても `double` を使う場合の鉄則（補足知識）

問題の出力自体が小数を要求している場合など、どうしても `double` を使わなければならない場合は以下の鉄則を守りましょう。

  • 定数は `.0` を付ける: `6 / 1000` ではなく `6.0 / 1000.0` と書き、小数演算であることを明示する
  • 出力精度を確認する: C++ の setprecision などで、問題が指定する絶対誤差・相対誤差に合った桁数を出力する
  • 誤差の扱いを決める: 固定の 1e-9 を足せば常に正しくなるわけではない。値の大きさや境界条件を確認し、整数化できる比較は整数で行う

4. まとめ & ポカミス防止チェックリスト

📌 今日の要点まとめ

  1. 除算の仕様を言語別に確認する: C++の整数 6 / 1000 は0、Python 3の同じ式は0.006
  2. 比較や最小化では整数化を検討し、途中計算のオーバーフローも確認する
  3. 分母が正の分数の比較 $A / B < C / D$ は、積の範囲を確認して $A \times D < C \times B$ に変換する
