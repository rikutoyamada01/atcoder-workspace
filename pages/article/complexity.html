🧮 計算量・TLEシミュレーター 計算回数と時間の目安を比べる

著者: rikuto yamada · 更新日: 2026年10月15日

⚡ 計算量・実行時間の概算

1秒あたり10⁸回の処理、制限時間2秒と仮定した比較ツールです。実行・正誤判定は行いません。実際の速度は言語・処理・入出力・実行環境に依存し、時間制限は問題ごとに異なります。

概算: この仮定では2秒以内（実測が必要）
計算回数目安: 約 3,500,000 回
仮定に基づく時間: 約 0.035 秒（実際の実行時間ではありません）

💡 初心者が知っておくべき「計算量と10⁸の壁」ルール

AtCoderの各問題には実行時間制限が設けられています。問題文に記載された制限を超えると TLE (Time Limit Exceeded) になります。2秒はこのツールの比較用の仮定であり、全問題共通のルールではありません。

1. 10⁸回という値は速度保証ではなく比較用の仮定

このツールは1秒あたり 10⁸回 と置いて計算回数を秒に換算しています。ビッグOには定数倍や処理の違いが含まれないため、この値をAtCoderサーバーの実測性能や合否の境界とは扱えません。実際のコードを問題の実行環境で測定してください。

2. 制約 N の大きさで選択すべきアルゴリズムが決まる

  • N ≤ 10⁵ ~ 2×10⁵: O(N) や O(N log N) の解法（二分探索、ソート、累積和、尺取り法）が必要。O(N²) の二重ループは処理回数が大きく、実用上厳しくなります。
  • N ≤ 2000: O(N²) の全対比較などは約4 × 10⁶回です。言語・処理・時間制限を確認します。ワーシャルフロイド法は O(N³) です。
  • N ≤ 15 ~ 20: O(2ᴺ) のビット全探索や再帰が使えます。

⚠️ 初心者がハマる！意外な計算量のワナ 3選

1. ループ内で vector::erase() や insert() を使うと O(N²) になる！

動的配列 vector の先頭や途中要素を削除・挿入すると、後ろの要素を詰めるために O(N) の移動処理が発生します。これをループの中で呼び出すと、全体で O(N²) となり TLE の原因になります。

2. 文字列の s = s + ch; は O(N)！s += ch; を使おう

s = s + ch; は毎回新しい文字列オブジェクトを生成して全体をコピーするため O(N) かかります。C++の1文字の末尾追加は s += ch; や s.push_back(ch); を使うと償却 O(1) で行えます。Pythonの文字列は別の仕様なので区別してください。

3. std::map の添字アクセス mp[key] は呼ぶたびに O(log N)

配列感覚で `mp[key]` を参照すると、裏で二分探索木を走査するため毎回 O(log N) のコストがかかります。ループ内で同じキーを何度も参照する場合は変数に保持するか、O(1) 平均の unordered_map を検討しましょう。

仕様の参照: C++標準草案の文字列サイズ取得、順列生成。グラフの計算量は頂点数V・辺数Eで、Pythonの大きな整数演算は桁数のコストも考慮してください。
