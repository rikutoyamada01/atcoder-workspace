💡 解法・アルゴリズム編 (Method Tags)

二分探索 (Binary Search)

#二分探索
計算量: O(log N)

ソート（昇順）されたデータの中から、目的の値を範囲を半分ずつ絞り込みながら超高速に探すアルゴリズムです。

  • 特徴: 100万個のデータからでも、たった約20回の比較で見つけ出せます。
  • 出題パターン: 「条件を満たす最小値/最大値を求めよ（答え二分探索）」で非常に頻出します。
// C++標準ライブラリ例 auto it = std::lower_bound(a.begin(), a.end(), target);

DP (動的計画法 / Dynamic Programming)

#DP
計算量: 状態数 × 遷移コスト

大きな問題を小さな部分問題に分解し、同じ計算を二度行わないように計算結果を配列にメモ（保存）しながら順に解いていく手法です。

  • 特徴: 再帰関数＋メモ化、または表埋め（ループ）で解きます。
  • 出題パターン: ナップサック問題、グリッドの移動経路数、文字列の編集距離など。
dp[i][j] = max(dp[i-1][j], dp[i-1][j - weight[i]] + value[i]);

累積和 (Prefix Sum)

#累積和
前計算: O(N) / クエリ: O(1)

配列の先頭からの合計値をあらかじめ前計算しておくことで、任意の区間 [L, R] の要素の和を一瞬で求める手法です。

  • 特徴: 通常のループだと毎回 O(N) かかる区間和計算を O(1) に削減できます。
  • 応用: 2次元に拡張した「2次元累積和」はグリッド問題で大活躍します。
// 区間 [L, R] の和 long long sum = S[R + 1] - S[L];

BFS / DFS (幅優先・深さ優先探索)

#BFS/DFS
計算量: O(V + E)

迷路やグラフ（頂点と辺）を探索する2大アルゴリズムです。

  • BFS (幅優先): キュー(Queue)を使い、スタート地点から近い順に波状に探索。迷路の最短手数を求めるのに最適。
  • DFS (深さ優先): 再帰関数を使い、行けるところまで奥深くまで進んで戻る。全パターンの探索や島・グループの連結判定に最適。
// BFS (キューを用いた最短手数計算例) queue<int> q; q.push(start); dist[start] = 0; while (!q.empty()) { int u = q.front(); q.pop(); for (int v : graph[u]) { if (dist[v] == -1) { dist[v] = dist[u] + 1; q.push(v); } } }

尺取り法 (Two Pointers)

#尺取り法
計算量: O(N)

条件を満たす区間の左端 L と右端 R を、芋虫（尺取り虫）のように右方向へすべらせて探索する手法です。

  • 特徴: 二重ループ O(N2) を O(N) に大幅に高速化できます。
  • 出題パターン: 「和が K 以下となる連続部分列の最長長さ」など、区間を広げると単調に条件が変化する場合に有効。
// 尺取り法 (和が K 以下の最長区間) int R = 0, sum = 0, ans = 0; for (int L = 0; L < N; L++) { while (R < N && sum + a[R] <= K) { sum += a[R]; R++; } ans = max(ans, R - L); if (R == L) R++; else sum -= a[L]; }

Union-Find (素集合データ構造)

#UnionFind
計算量: ほぼ O(1) (α(N))

要素同士を「同じグループに統合する (Union)」処理と、「2つが同じグループか調べる (Same/Find)」処理を爆速で行うデータ構造です。

  • 特徴: 経路圧縮により実質ほぼ定数時間で動作します。
  • 用途: 友達グループの管理、無向グラフの閉路検出、最小全域木（クラスカル法）。
// AtCoder Library (ac-library) での使用例 #include <atcoder/dsu> atcoder::dsu d(N); d.merge(u, v); // 頂点 u と v をグループ統合 bool same = d.same(u, v); // 同じグループか判定

貪欲法 (Greedy Algorithm)

#貪欲法
計算量: 問題のソート順等に依存 (O(N log N))

先のことを細かく考慮せず、「その瞬間に最も有利な選択」を繰り返すことで全体の最適解を得る手法です。

  • ポイント: コードはシンプルになりますが、「本当に貪欲法で最適解になるか（証明）」を意識することが大切です。
  • 例: コインの枚数を最小にするお釣り、区間スケジュール問題。
// 区間スケジューリング問題 (終了時刻で昇順ソートして選ぶ) sort(tasks.begin(), tasks.end(), [](auto &a, auto &b) { return a.end_time < b.end_time; }); int last_end = 0, count = 0; for (auto &t : tasks) { if (t.start_time >= last_end) { count++; last_end = t.end_time; } }

全探索 (Brute-Force Search)

#全探索
計算量: パターン数 (O(2^N), O(N!))

考えられるすべての可能性を漏れなく1つずつ試す、最も確実で基本となる解法です。

  • ポイント: N が小さい（N ≤ 15 ～ 20）場合は全探索が正解になります。
  • バリエーション: ループ全探索、ビット全探索（1 << N）、順列全探索（next_permutation）。
// ビット全探索 (2^N 通りの組み合わせを全試行) for (int bit = 0; bit < (1 << N); bit++) { for (int i = 0; i < N; i++) { if (bit & (1 << i)) { /* i 番目の要素を選ぶ */ } } }

コーナーケース (Edge Cases)

#コーナーケース

問題の境界値（端の入力例）でプログラムが予期せぬ挙動をするバグです。提出後の WA（誤答）の最大の原因です。

  • 代表例: N = 1 や N = 0 のとき、要素が全て同じ時、負の数が含まれる時、配列の先頭/末尾。
  • 対策: 「N = 1 でも正しく動くか？」を意識して手動テストを追加しましょう。
// N = 1 の特例判定例 if (N == 1) { cout << 0 << endl; // 特例として即座に出力して終了 return 0; }

オーバーフロー (Integer Overflow)

#オーバーフロー

型が扱える数値の上限を超えてしまい、数値がマイナスの大きな値に反転してしまう現象です。

  • 数値の壁: C++の int 型は最高で約 21億 (2 × 109) までしか入りません。掛け算 N × M や累積和で簡単に溢れます。
  • 対策: 迷ったら long long 型（約 9 × 1018 までOK）を使いましょう。
// BAD: int 同士の掛け算で溢れて負の値になる int a = 1000000, b = 1000000; long long ans1 = a * b; // × (a * b は int 型で溢れる) // GOOD: long long 型で計算する long long ans2 = (long long)a * b; // ○ (10^12 が正しく入る)

TLE (実行時間制限超過)

#TLE(計算量)

プログラムの計算に時間がかかりすぎ、制限時間（通常2秒）を超過したエラーです。

  • 目安: AtCoder の 2 秒制限は、おおむね 108 回（1億回）の計算が限界です。
  • 例: N = 105 のときに O(N2) = 1010 回の二重ループを書くと確定で TLE します。O(N log N) などに改善しましょう。
// TLE 例: N = 10^5 のときに 10^10 回計算してタイムアウト for (int i = 0; i < N; i++) { for (int j = 0; j < N; j++) { ... } // TLE! (2秒オーバー) } // AC 例: 二分探索で O(N log N) に改善してクリア for (int i = 0; i < N; i++) { binary_search(...); // AC! (約 10^5 * 17 回で約 0.01 秒) }

配列外参照 / RE (Runtime Error)

#配列外参照/RE

確保した配列のサイズを超えてアクセスした際（例: サイズ N に a[N] や a[-1] でアクセス）にプログラムが異常終了するエラーです。

  • 対策: 1-indexed（1始まり）の問題では、配列サイズを N + 5 など多めに確保しておくと安心です。
// BAD: 1-indexed (a[N]) でアクセスすると宣言サイズオーバー int a[N]; // 0 ~ N-1 しか確保されないため a[N] でクラッシュ! // GOOD: N + 5 など余裕をもって多めに確保する vector<int> a(N + 5); // 安全!

初期化忘れ (Uninitialized Variables)

#初期化忘れ

複数のテストケースやループ処理の中で、変数や配列の値を 0 や初期値に戻し忘れたことで生じるバグです。

  • 症状: 手元のサンプルテスト1個目は通るのに、連続実行すると値がおかしくなる場合、初期化忘れを疑いましょう。
// ループの先頭で必ず初期化 for (int t = 0; t < T; t++) { int sum = 0; // ループ内でリセットを忘れずに! vector<int> counts(N, 0); // 配列も毎回 0 で初期化 ... }
