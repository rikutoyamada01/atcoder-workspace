## 💡 解法・手法 (Algorithms & Concepts)

### 1. 二分探索 (Binary Search)
* **概要**: 整列（ソート）済みのデータから、探したい値を中央の値と比較しながら探索範囲を半分ずつ絞り込んで検索する高速な手法。
* **計算量**: $O(\log N)$（要素数が100万個でも約20回の比較で探索完了）。
* **よく使う場面**: 「答えの値を仮定して、それが条件を満たすか判定する」型の問題（答え二分探索）。

### 2. DP (動的計画法 / Dynamic Programming)
* **概要**: 大きな問題を小さな部分問題に分解し、同じ計算を繰り返さないよう計算結果を配列にメモ（保存）しながら解く手法。
* **計算量**: 状態数 $\times$ 1状態あたりの遷移時間。
* **よく使う場面**: ナップサック問題、グリッドの最短経路数、最適化問題など。

### 3. 累積和 (Prefix Sum)
* **概要**: 配列の先頭からの合計値をあらかじめ前計算しておくことで、任意の区間 $[L, R]$ の合計値を $O(1)$ の一瞬で求める手法。
* **計算量**: 前計算 $O(N)$、クエリ $O(1)$。
* **よく使う場面**: 区間和の多数の問い合わせ、2次元グリッドの矩形和など。

### 4. BFS / DFS (幅優先探索 / 深さ優先探索)
* **概要**: グラフやグリッド（迷路・マス目）を探索するアルゴリズム。
  * **BFS (Breadth-First Search)**: キュー(Queue)を使い、近い場所から順に波状に調べる。重みなしグラフの**最短距離**を求めるのに便利。
  * **DFS (Depth-First Search)**: スタック(Stack)や再帰関数を使い、行けるところまで奥深くまで進んで戻る。**全探索**や**連結成分の検出**に便利。

### 5. 尺取り法 (Two Pointers)
* **概要**: 条件を満たす区間の左端 $L$ と右端 $R$ を、右方向へすべらせるように順番に進めることで、全探索 $O(N^2)$ を $O(N)$ に高速化する手法。
* **よく使う場面**: 「連続する部分列で条件を満たす最小/最大長を求める」場合。

### 6. Union-Find (素集合データ構造)
* **概要**: 要素同士の「グループ結合（Union）」と「同じグループに属するかどうかの判定（Find）」をほぼ $O(1)$ で高速に行うデータ構造。
* **よく使う場面**: 連結成分の管理、無向グラフの閉路検出、最小全域木（クラスカル法）など。

### 7. 貪欲法 (Greedy Algorithm)
* **概要**: 全体の先のことを細かく考慮せず、「その場その場で最も有利な選択」を繰り返すことで全体の最適解を得る手法。
* **ポイント**: 貪欲法が正当である証明（「後悔しない選択か」）が必要なことが多い。

### 8. 全探索 (Brute-Force Search)
* **概要**: 考えられるすべてのパターンを漏れなく試す最も基本かつ確実な手法。
* **ポイント**: 制約（$N \le 10$ や $N \le 20$ 等）が小さい場合は、ビット全探索や順列全探索（`next_permutation`）が威力を発揮。

## ⚠️ 詰まった原因 & エラー用語 (Common Errors)

### 1. コーナーケース (Edge Cases)
* **概要**: 問題の入力条件の端（例外的な境界値）でプログラムが予期せぬ挙動をするバグ。
* **よくある例**:
  * $N = 1$ や $N = 0$ のときの特例処理漏れ
  * ループの境界条件（$<` か `<=`, $0$ インデックスと $1$ インデックス）
  * 全ての値が同じ場合、負の数が含まれる場合

### 2. オーバーフロー (Integer Overflow)
* **概要**: 32bit整数型（C++の `int` 等）の扱える範囲（約 $-2.1 \times 10^9 \sim 2.1 \times 10^9$）を超えて数値が溢れ、予期せぬ負の値になる現象。
* **対策**: C++では掛け算や累積和を扱う変数に `long long` 型（最大約 $9 \times 10^{18}$）を使用する。

### 3. TLE (Time Limit Exceeded / 実行時間制限超過)
* **概要**: アルゴリズムの計算量が多すぎて、AtCoderの制限時間（通常2秒 $\approx 10^8$ 回の計算ステップ）内に処理が完了しなかった状態。
* **対策**: 計算量オーダを見直し、$O(N^2) \rightarrow O(N \log N)$ などアルゴリズムを改良する。

### 4. 配列外参照 / RE (Runtime Error)
* **概要**: 配列の宣言サイズを超えるインデックス（例: サイズ $N$ の配列に `a[N]` や `a[-1]` でアクセス）に触れてプログラムがクラッシュするエラー。
* **対策**: 配列サイズを余裕を持って大きめ（`N + 5` など）に確保する。

### 5. 初期化忘れ (Uninitialized Variables)
* **概要**: 変数や配列を $0$ や初期状態に戻し忘れたことで、テストケース間やループ間で意図しないゴミデータが残留するバグ。
